# 01 · 总体架构设计

## 1. 产品定位

面向个人投资者的**分红记账与现金流预测工具**。核心能力：

1. 多市场持仓管理（A股 / 美股 / 港股 / 基金 / 债券），支持同一标的**多批次买入/卖出/送转**
2. 分红记录：按**股权登记日**自动计算可参与分红的批次与股数，自动估算税费与税后到账
3. 分红预告：官方分红预案（爬虫采集 + 人工审核）推送、12 个月分红现金流预测
4. 多维度统计：年度/市场/持仓贡献、现价股息率 vs 成本股息率（Yield on Cost）、派息节奏
5. 多用户数据隔离；Web / App / 微信小程序三端同构；配套运营后台维护分红基础数据

## 2. 技术选型

### 2.1 后端

| 组件 | 选型 | 理由 |
|---|---|---|
| 语言/框架 | Python 3.11+ / **FastAPI** | 异步轻量、自带 OpenAPI 文档（/docs）、Pydantic 类型校验 |
| ORM | **SQLModel**（SQLAlchemy 2.0 + Pydantic 融合） | 模型即 Schema，代码量少；迁 PostgreSQL 仅改连接串 |
| 数据库 | **SQLite**（WAL 模式） | 最省内存：无独立进程，连接内存约 2–5MB；单文件易备份 |
| 鉴权 | JWT（access + refresh）/ **pyjwt** + **passlib[bcrypt]** | 无状态，三端统一 |
| 定时任务 | **APScheduler**（进程内） | 汇率每日更新、分红预告自动匹配、爬虫调度；无需额外中间件 |
| HTTP/爬虫 | httpx + selectolax/BeautifulSoup | 采集交易所/公司公告 |
| CSV | pandas 或标准库 csv | 导入导出 |
| 后台 | **sqladmin**（P1 阶段） | 从 SQLModel 模型自动生成 CRUD 后台，挂在 /admin |
| 校验 | Pydantic v2 | 请求/响应模型强校验 |

### 2.2 前端

| 组件 | 选型 | 说明 |
|---|---|---|
| 框架 | **uni-app（Vue3 + TS + Vite）** | 一套代码编译 H5 / Android/iOS App / 微信小程序 |
| 状态管理 | Pinia | token、用户信息、缓存 |
| UI 库 | uv-ui（或 uview-plus） | 三端兼容组件库 |
| 图表 | **uCharts**（全端默认）；H5 可选 ECharts | 小程序 canvas 限制，ECharts 用 lime-echart 封装 |
| 请求 | uni.request 封装拦截器 | 自动带 JWT、401 跳登录 |

### 2.3 运行环境（目标部署）

- 1 台最低配云服务器（1C1G 即可）：FastAPI 常驻内存约 60–80MB，SQLite 文件库
- 操作系统 Linux；Python 以 venv/uv 运行；进程管理 systemd / uvicorn + --workers 1（SQLite 单写者，见 §6）
- HTTPS：Caddy 或 Nginx 自动证书（**微信小程序强制要求 HTTPS 且域名备案**）

```
┌──────────────────────────────────────────────────────────────┐
│  客户端层                                                      │
│  ┌────────────┐   ┌──────────────┐   ┌────────────────────┐  │

│        └─────────────────┼─────────────────────┘              │
│              HTTPS / JSON · Bearer JWT                         │
├──────────────────────────┼───────────────────────────────────┤
│                          ▼                                     │
│  FastAPI 应用（单体，模块分层）                                  │
│  ┌──────────┐ ┌──────────┐ ┌───────────┐ ┌────────────────┐   │
│  │ auth 认证 │ │ holdings │ │ dividends │ │ schedules 预告  │   │
│  │ users 用户│ │ lots 批次 │ │ stats统计 │ │ admin 后台接口  │   │
│  ├──────────┴───────────┴───────────┴─────────────────────┤  │
│  │  Service 层：分红归属计算 / 税费 / 汇率折算 / 统计聚合      │  │
│  ├───────────────────────────────────────────────────────┤  │
│  │  SQLModel / SQLAlchemy 2.0（全部查询强制 user_id 过滤）    │  │
│  └───────────────────────────┬───────────────────────────┘   │
│                              │                                │
│  ┌──────────────┐  ┌─────────┴────────┐  ┌────────────────┐   │
│  │ APScheduler  │  │ SQLite (WAL)     │  │ 外部数据源       │   │
│  │ ·汇率日更新   │  │ xi.db 单文件      │  │ 央行汇率/交易所  │   │
│  │ ·预告自动匹配 │  │ + 每日备份文件    │  │ 公告/微信API    │   │
│  │ ·爬虫采集    │  │                  │  │                │   │
│  └──────────────┘  └──────────────────┘  └────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

设计原则：**模块化单体**（Modular Monolith）。不引入微服务/Redis/消息队列——单服务器、千级用户规模下全部由 SQLite + 进程内调度承担；未来需要拆分时按模块边界拆服务。

## 5. 安全设计

| 项 | 方案 |
|---|---|
| 密码 | bcrypt 哈希（passlib），不存明文；强度校验 ≥8 位 |
| 认证 | JWT：access_token 2 小时、refresh_token 30 天；Header `Authorization: Bearer <token>` |
| **数据隔离** | 所有业务查询在 Service 层统一附加 `WHERE user_id = :uid`；写入时强制填充 `user_id`；删除/修改前校验资源归属，越权返回 404（不暴露资源存在性） |
| 管理员隔离 | 管理员为独立体系（users.role=admin，登录入口 /admin 单独签发带 scope 的 token）；管理员对用户数据**只读**，所有操作写 `admin_operation_logs` |
| 小程序登录 | wx.login 拿 code → 后端 code2session 换 openid → 绑定/创建用户 → 签发 JWT；openid 落库 |
| 输入校验 | Pydantic 白名单校验；金额 Decimal 存储（见 02 文档），浮点不入库 |
| 接口限流 | 登录/注册接口按 IP 限流（slowapi 或简单内存计数），防爆破 |
| 传输 | 全链路 HTTPS；小程序后台配置 request 合法域名 |
| 备份 | SQLite 文件每日凌晨复制到 backups/xi-YYYYMMDD.db，保留 30 天 |
| 审计 | 后台所有写操作记录操作人、对象、前后值摘要 |

## 6. SQLite 并发与容量

- 开启 `PRAGMA journal_mode=WAL`（读不阻塞写、写不阻塞读）+ `PRAGMA busy_timeout=5000`（写锁冲突等待 5s）
- SQLite 为**单写多读**：uvicorn 单 worker + 多协程足够；写操作短事务提交
- 容量估算：单用户 ~100 持仓 / 500 批次 / 500 分红 ≈ 2000 行；**1 万用户 ≈ 2000 万行，SQLite 仍可承受**（查询都走 user_id 索引）
- 迁移信号：日活上千且写锁等待频繁时，切换 PostgreSQL——SQLModel 仅改 `DATABASE_URL`，SQL 方言差异仅少数字段（见 02 文档迁移约定）

## 7. 部署拓扑（最简）

```
小程序/App/H5 ──HTTPS──▶ Caddy/Nginx(443, 自动证书)
                            ├── /          → FastAPI 静态托管 H5 构建产物
                            ├── /api/*     → uvicorn 127.0.0.1:8000
                            └── /admin     → FastAPI(sqladmin)
FastAPI(systemd 守护, 自动重启) ── data/xi.db（每日备份）
```

- H5 构建产物直接由 FastAPI `StaticFiles` 托管，**一个服务、一个端口、一个数据库文件**即可跑全产品
- App 端：HBuilderX 云打包 APK/IPA；小程序端：微信开发者工具上传提审（详见 05 文档）
