# 06 · 运营后台设计

> 阶段：P1（P0 先做用户端闭环）。原型见 `prototype.html` 左下角「🛠️ 运营后台」（5 页）。

## 1. 实现策略：sqladmin + 1 个自定义页

| 内容 | 实现方式 | 工作量 |
|---|---|---|
| 登录鉴权 | 独立管理员入口 `/admin`，users.role=admin，sqladmin 认证后端对接 JWT/会话 | ~50 行 |
| 用户管理 | **sqladmin ModelView 自动生成**（列表/搜索/封禁/重置密码加动作按钮） | ~30 行 |
| 汇率/税率/公告/反馈 | **sqladmin 自动 CRUD** | ~60 行 |
| 操作日志 | sqladmin 只读 ModelView | ~10 行 |
| **分红预案审核流** | **自定义 FastAPI 页面/接口**（状态机 + 置信度 + 批量操作，sqladmin 不擅长工作流） | 1 个页面 + 11.3 接口 |

- 后台挂载在主 FastAPI 进程内，路由前缀 `/admin`（页面）+ `/api/admin`（接口）
- 与用户端同源同库；管理员账号就是 users 表中 role=admin/super_admin 的记录

## 2. 管理员权限模型

| 角色 | 权限 |
|---|---|
| super_admin | 全部：审核、用户封禁、汇率税率、公告、反馈、日志 |
| admin | 审核、反馈处理、公告；不可改税率/汇率、不可封禁其他管理员 |
| user | 无权访问 /admin（拦截 403） |

权限红线（硬约束）：
- 管理员对用户业务数据（holdings/lots/dividends）**只读**，任何后台代码路径不提供写接口
- 所有写操作落 `admin_operation_logs`（操作人/动作/对象/前后值摘要/IP）

## 3. 页面逐页设计（字段/筛选/按钮权限）

### 3.1 运营看板（首页）

- 指标卡：注册用户总数（本周新增）、DAU（DAU/MAU）、用户分红记录总数（持仓数/批次数）、待审核预案数（高亮，点击跳审核页）
- 图表：近 30 天新增用户（柱）+ 日活（线）；预案数据来源环图（爬虫/人工/用户提交）
- 数据条：爬虫今日采集 / 今日已发布 / 低置信度待人工
- 接口：`GET /api/admin/stats/overview`
- 权限：admin 可读

### 3.2 分红预案审核（核心页）

**筛选**：状态 Tab（待审核 7 / 已发布 342 / 已驳回 18）、市场下拉、关键字、置信度区间
**顶部按钮**：🕷️ 立即爬取公告（super/admin）、+ 手动录入预案（super/admin）、☑️ 批量发布 / 批量驳回（v1.1 新增，需先勾选多行）

> **批量审核**（v1.1）：列表首列支持 checkbox 多选，勾选后点「批量发布」一次发布多条 pending 预案（校验逻辑同单条，任一失败整体回滚）；「批量驳回」需弹框输入驳回理由。接口见 04 §8.3。

**列表字段**：

| 列 | 来源 | 说明 |
|---|---|---|
| 市场/代码/名称 | schedules | 市场徽标 |
| 类型 | div_type | 现金/送股 |
| 每股分红 dps | schedules | 原币种 4 位小数 |
| 股权登记日/除权日/派息日 | schedules | 空值显示「未公告」 |
| 来源 | source | 🕷️爬虫 / 人工 / 👤用户提交 |
| 置信度 | confidence | 进度条：≥90% 绿 / 70–90% 黄 / <70% 红 |
| 状态 | status | 待审核(黄)/已发布(绿)/已驳回(红) |
| 操作 | — | 通过 / 驳回 / 编辑 |

**按钮权限**：通过、驳回、编辑 = admin+；行内「通过」需二次确认；「驳回」必填驳回原因。
**交互**：
- 支持勾选批量通过（仅置信度 ≥90% 的行允许批量，其余提示需逐条核对）
- 通过 → status=published → 写日志 → 异步触发全体相关用户 auto-match（生成 pending 分红）
- 重复发布被唯一索引拦截 → 错误 5001 提示「该标的除权日预案已存在」
- 低置信度行高亮底色，用户提交行显示提交人

接口：`GET/POST /api/admin/schedules`、`/{id}/approve`、`/{id}/reject`、`/crawl`（见 04 §11.3）

**爬虫任务（APScheduler 每日两次：8:00/18:00）**：
- 源：交易所公告（A股）、公司 IR 页面（美股/港股）、基金公司公告
- 解析：market/code/name/三个日期/dps/币种/公告标题(raw_title)
- 置信度评分：官网/交易所原文且字段完整 0.90–0.98；门户转载 0.70–0.89；解析缺字段 <0.70
- 入库 pending；同 (market,code,ex_date) 已存在则跳过

### 3.3 用户管理

**筛选**：关键字（用户名/邮箱/ID）、状态、角色、分页
**列表字段**：ID、用户名、邮箱（脱敏显示）、持仓数、分红记录数、累计分红(折CNY)、注册时间、最近登录、角色、状态
**行操作**：查看数据（只读：该用户持仓/分红汇总，调用 `/users/{id}/data`）、重置密码（super/admin，返回一次性临时密码）、封禁/解封（super/admin；不可操作 admin 及以上）
**接口**：04 §11.2
**脱敏**：邮箱/手机号列表默认掩码（vi****@163.com），详情页仅 super_admin 可见完整值

### 3.4 汇率与税率

- 汇率卡：USD/CNY、HKD/CNY 现值 + 更新时间 + 🔄 立即获取（调央行中间价，super/admin）
- 历史汇率表：按日期查询（sqladmin）
- 税率表（tax_rules）：市场/税务情形/税率/持股天数区间/说明/启用开关；编辑仅 super_admin；税率被分红计算实时引用，修改不追溯历史分红
- 提醒与预告规则开关：预案通过后自动推送、派息日前 3 天/当天提醒、季派月派自动推算、允许用户提交预案
- 接口：`/api/admin/rates*`、`/api/admin/tax-rules`、规则开关入 settings 或配置表（V1 可入全局 config）

### 3.5 公告与反馈

- 公告：标题 + 内容富文本/纯文本 + 发布/草稿/下线；发布后用户端 `/announcements` 拉取，首页横幅
- 反馈列表：用户、内容、联系方式、状态（待处理/已采纳/排期中/已上线/驳回）、回复
- 处理动作：选状态 + 回复内容 → 用户端「我的-反馈」可见
- 接口：04 §11.5/11.6

## 4. 后台页面 ↔ 接口映射

| 页面 | 接口 |
|---|---|
| 看板 | `GET /api/admin/stats/overview` |
| 预案审核 | `GET /api/admin/schedules`、`POST .../approve|reject`、`POST /crawl`、`POST /api/admin/schedules` |
| 用户管理 | `GET /api/admin/users`、`GET .../{id}/data`、`POST .../{id}/ban|unban|reset-password` |
| 汇率税率 | `GET/POST /api/admin/rates`、`/rates/refresh`、`GET/PUT /api/admin/tax-rules/{id}` |
| 公告 | `POST/PATCH /api/admin/announcements` |
| 反馈 | `GET /api/admin/feedback`、`PATCH /api/admin/feedback/{id}` |
| 日志 | `GET /api/admin/logs`（只读） |

## 6. 数据源与采集策略（v1.1 更新）

| 市场 | 数据源 | 频率 | 置信度 | 说明 |
|---|---|---|---|---|
| A 股 | 东方财富数据中心 `RPT_SHAREBONUS_DET` | 每日 08:05 / 18:05 | 0.90-0.98 | 公开接口，无需 key |
| 美股 | Alpha Vantage `TIME_SERIES_MONTHLY_ADJUSTED` | 每日 08:05 / 18:05 | 0.75 | 需配置 `XI_AV_API_KEY`（免费申请 alphavantage.co），白名单 5 只（AAPL/MSFT/JNJ/KO/PG），限速 5 次/分钟 |
| 港股/基金 | 手动录入 | — | 0.60-1.00 | 暂无免费数据源 |

- 离线模式：`XI_CRAWL_OFFLINE=1` 跳过所有爬虫分支
- 无 `XI_AV_API_KEY` 时自动跳过美股分支，不影响 A 股
- 爬虫失败静默降级，不抛异常，errors 数组返回原因
