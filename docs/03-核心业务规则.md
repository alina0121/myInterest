# 03 · 核心业务规则

> 本文档定义后端 Service 层必须严格实现的计算口径。所有金额计算用 Python `Decimal`，
> 落库前四舍五入（每股 4 位、金额 2 位）。日期只比较日历日。

## 1. 多批次持仓模型

### 1.1 概念

- **持仓（holding）**：一只标的一条，静态信息（市场/代码/名称/币种/账户/频率）
- **批次（lot）**：每次交易一条：买入(buy) / 卖出(sell) / 送股转增(bonus_share)
- 「当前持仓数量、平均成本、总投入」**实时聚合，不落库**

### 1.2 持仓聚合公式

设持仓下所有批次按 `trade_date` 排序：

```
当前数量 shares_now = Σ buy.shares + Σ bonus_share.shares − Σ sell.shares

总投入（成本）cost_total = Σ buy.shares×buy.price + buy.fee        （卖出不冲减成本，先进先出处理见 1.4）
平均成本 avg_cost = cost_total ÷ 当前数量（当前数量=0 时记为 0，持仓标记「已清仓」）

每批次累计分红 lot_dividends(lot) = Σ dividend_allocations(该 lot 的 net)
```

接口返回的 `shares_now / avg_cost / cost_total` 均为计算字段，前端不可提交。

### 1.3 批次新增/编辑规则

- 新增批次：校验 `holding_id` 归属当前用户；`shares>0`；buy 时 `price>0`，bonus_share 时 `price=0`
- 卖出校验：**卖出后净持仓不得为负**（`sell.shares ≤ 当前数量`）
- 批次删除：`dividend_allocations.lot_id` 置 NULL 但保留快照（lot_date/shares/gross）
- 批次变更（改日期/数量）→ 触发该持仓**所有相关分红重算**（见 §2.4）

### 1.4 卖出与先进先出（FIFO，用于 A 股持股期限计税）

A 股红利税按「持股期限」分档（§3.1）。卖出时按 FIFO 核销批次股数，被核销批次的持有期 =
`卖出日 − 该批次买入日`；该批次对应的、此前按低档暂扣的税在卖出时补扣差额。
V1 简化处理：分红时按**登记日时点**批次持有天数估算税率并展示「估算」标记，用户可手工改税费
（`tax_overridden=1` 后自动重算跳过）；卖出补税在 V2 做自动提示。

## 2. 分红与批次归属（核心算法）

### 2.1 关键日期

| 日期 | 含义 | 归属作用 |
|---|---|---|
| 股权登记日 record_date | 收盘后持有即享有分红 | **归属判定日**：`lot.trade_date ≤ record_date` 的批次才参与 |
| 除权除息日 ex_date | 买入不再享有本次分红 | 美股 record_date=ex_date（按经纪商口径取 ex_date 判定） |
| 派息日 pay_date | 现金到账 | 统计/汇率折算按此日 |

### 2.2 可参与分红股数（eligibility）

对一笔分红（holding + record_date）：

```
eligible_lots = 该持仓下 direction∈{buy, bonus_share} 且 trade_date ≤ record_date 的批次
eligible_shares = Σ eligible_lots.shares − Σ( sell 中 trade_date ≤ record_date 的 shares，FIFO 核销)
gross_amount   = eligible_shares × dps
```

- 卖出核销采用 FIFO：最早的买入批次先核销
- 若 `eligible_shares = 0` → 不允许生成该分红（或标记异常，返回错误码 40002）

### 2.3 批次级归属明细（dividend_allocations）

每个**未被卖出核销完**的 eligible_lot 生成一行：

```
shares_alloc = 该批次在 record_date 时仍持有的股数（= lot.shares − 该批次被 FIFO 核销数）
gross_alloc  = shares_alloc × dps
tax_alloc    = gross_alloc × 适用税率（§3，按该批次 market + 持有天数分档）
net_alloc    = gross_alloc − tax_alloc
lot_date 快照 = lot.trade_date
```

原型示例（茅台 2023-06-28 派息，dps=25.91）：批次1（2022-03-15 买 60 股）参与；
批次2（2023-09-20 买入，晚于登记日）**不产生 allocation 行**，前端在分红历史标注「批次尚未买入，不参与本次分红」（由归属计算结果推导：该批次不在 eligible_lots 中）。

### 2.4 重算触发时机

1. 新增/编辑/删除批次后，重算该持仓 `record_date >= 变更批次 trade_date` 的所有分红
2. 已手工改税（`tax_overridden=1`）的分红保留税费，仅重算股数与金额
3. 已确认到账（status=confirmed）的分红重算需用户在前端确认（避免静默改历史账）

### 2.5 分红两个状态

- `pending`（待到账）：由已发布预案自动匹配生成，或用户预录入；进入「即将到账」与提醒
- `confirmed`（已到账）：用户确认到账后转入；计入全部已到账统计与日历实心标记
- 自动匹配：`schedules.status=published` 后，定时任务为「持有该 market+code 且 eligible_shares>0」的每个用户生成 pending 分红（幂等：同 schedule_id+holding_id 唯一）

## 3. 税费规则

### 3.1 税率表（tax_rules，后台可配）

| 市场 | 情形 | 税率 | 判定口径 |
|---|---|---|---|
| A股 | 持股 > 1 年 | 0% | 批次 `record_date − trade_date ≥ 366` 天 |
| A股 | 持股 1 个月~1 年 | 10% | 31~365 天 |
| A股 | 持股 ≤ 1 个月 | 20% | ≤ 30 天 |
| 美股 | W-8BEN 中国居民 | 10% | 固定（券商代扣预提税） |
| 港股通 | 内地个人 | 20% | 固定（H股 10%+红利税 10%，中登代扣） |
| 基金 | 公募分红 | 0% | 固定 |

### 3.2 计算

- 按**批次**分档：每个 allocation 用该批次持有天数对应税率（A股）；美股/港股/基金用固定税率
- `dividend.tax = Σ allocation.tax`，`net_amount = Σ allocation.net`
- 前端税费字段始终可编辑（实际到账可能与估算不同，如券商口径差异）

## 4. 汇率与多币种折算

### 4.1 汇率获取

- 每日定时任务取 USD/CNY、HKD/CNY（央行中间价，失败则沿用上一交易日并标记）
- 落 exchange_rates（base, quote, rate, rate_date 唯一）

### 4.2 折算口径

- 原币金额始终保留（gross/net 按分红币种存）
- **统计折算用「派息日 pay_date 当日汇率」**；查不到则用最近前一交易日
- 本位币统一折 CNY：`cny_amount = original_amount × rate(base→CNY)`（CNY 汇率=1）
- 用户 `base_currency` 字段预留给未来多本位币（V1 固定折 CNY 展示）

## 5. 统计指标口径

| 指标 | 口径 |
|---|---|
| 年度分红（税前/税后） | 该自然年 `pay_date` 且 status=confirmed 的 net 之和（折 CNY） |
| 本月到账 | 当月 pay_date 已到账笔数与金额 |
| 累计分红 | 全部 confirmed 的 net 之和 |
| TTM 分红 | pay_date 在 [今天−365, 今天] 的 confirmed net 之和 |
| **现价股息率** | 近 12 个月每股分红(dps TTM) ÷ 当前市价 ×100%（市价为可选字段，V1 手填/无则只展示成本股息率） |
| **成本股息率 YoC** | 该持仓 TTM 每股分红 ÷ 加权平均成本 avg_cost ×100%（多批次加仓后自动反映摊薄/抬高） |
| 持仓累计分红 | 该持仓全部 confirmed net（原币展示） |
| 市场占比 | 按市场分组 Σ(net 折 CNY) |
| 分红频率 | holdings.freq（后台/爬虫回填；用户可改） |

## 6. 未来 12 个月分红预测

对每只持仓生成未来 12 个月预测序列：

1. **已公告部分**：dividend_schedules 中 status=published 且 pay_date 在未来 12 月，按该用户 eligible_shares × dps 计入对应月份（柱状图「已公告预案」）
2. **推算部分**：按 freq 与该标的**历史派息月份规律**（取近 3 年同月份 dps 均值；无历史则跳过）生成预测（「按历史推算」）
3. 输出 12 个月的月度金额（折 CNY）+ 每笔来源标记；季派/月派标的自动按月/季节奏展开

## 7. 爬虫置信度与审核流（schedules）

```
采集来源 → confidence 评分 → 入库 status=pending
  · 交易所/公司公告原文（结构化字段齐全）  ≥0.90  → 仍需人工过目，但置顶「建议通过」
  · 财经媒体/行情站转载                    0.70~0.90 → 待审核
  · 用户提交                              <0.70    → 「需人工核对」红色高亮
人工审核 → published（对用户可见 + 触发自动匹配）/ rejected（必填 reject_reason）
```

- 幂等：同 (market, code, ex_date) 已 published 的预案唯一索引拦截重复发布
- 用户提交入口：V2 开放（开关在后台「提醒与预告规则」）

## 8. 日历生成规则

- 取用户当月 dividends：confirmed → 绿色「已到账」；pending → 琥珀色「预告」
- 同一天多笔显示角标数字；点击日期展开当日列表
- 全月/多月数据来自 `GET /api/calendar?year=&month=`，前端画格子

## 9. 导入导出规则

- **持仓 CSV**（支持多批次）：字段 `market,code,name,trade_date,direction,shares,price,fee,currency,account,note`
  - 同 code 多行 → 自动归并为 1 个 holding + N 个 lot
  - 冲突处理：code 已存在 → 仅追加批次，不覆盖既有批次
- **分红 CSV**：`market,code,ex_date,record_date,pay_date,dps,tax,currency`
  - 按 market+code 匹配持仓；自动跑归属算法生成 allocations
  - 无法匹配（无持仓）的行进入导入报告「跳过」列表，不静默丢弃
- **导出**：全量 JSON（含用户所有表）+ 各表 CSV；导入报告返回 `{inserted, updated, skipped[], errors[]}`

## 10. 权限矩阵（接口级）

| 资源 | 普通用户 | 管理员(admin/super_admin) |
|---|---|---|
| 自己的 holdings/lots/dividends/settings | 增删改查 | 只读（客服排查） |
| 他人数据 | 不可见（404） | 只读 |
| schedules 预案 | 只读已发布 | 全部状态可查 + 审核 |
| tax_rules / exchange_rates | 只读 | 可改 |
| announcements | 只读已发布 | 发布/下线 |
| feedback | 提交/看自己 | 查看全部/处理 |
| admin 操作日志 | 不可见 | 可查（不可改） |
